RecoverX — AI-Native Payment Recovery Console
A full-stack fintech/payment-recovery prototype built for a Razorpay-focused buildathon in India.

RecoverX detects failing and at-risk payments, runs an agent-driven recovery workflow, and gives operators a centralized console to investigate incidents, simulate recovery strategies, review risk, approve actions, and track outcomes.

RecoverX — Don't let a failed payment become a lost payment.

Frontend Notifications / Live Indicators
Every AI/agent result in the product — including root cause, risk score, recommended strategy, and simulation outcome — is generated by a deterministic demo agent engine in the backend rather than being a static UI label.

See backend/README.md and backend/docs/API.md for the exact logic behind each endpoint.

No live money movement, bank call, or payment-provider API call happens in this build. Every write endpoint that could resemble a financial action is explicitly implemented as a simulation and labelled accordingly in both the API responses and UI.

💳 Razorpay Integration
RecoverX is designed around Razorpay-style payment recovery workflows.

The current buildathon version uses a deterministic simulation layer rather than moving real money. This allows the complete recovery lifecycle to be demonstrated safely:

Payment
   ↓
Failure / Risk Detection
   ↓
Root-Cause Investigation
   ↓
Recovery Strategy
   ↓
Risk & Autonomy Check
   ↓
Human Approval
   ↓
Simulated Execution
   ↓

The payment and recovery service layer is structured so that a real payment-provider integration can replace the simulation layer in a production deployment.

🧠 Agent Engine
RecoverX uses a deterministic, agent-driven decision engine to reproduce realistic payment-recovery behaviour without requiring external AI APIs.

The demo agents cover:

Anomaly Agent — identifies suspicious or abnormal payment behaviour
Root-Cause Agent — determines the likely reason for a payment incident
Recovery Strategy Agent — recommends an appropriate recovery action
Risk / Autonomy Agent — determines whether an action can proceed automatically or requires human approval
Outcome Agent — estimates recovery probability and expected recovery value
The deterministic approach keeps the buildathon demo:

Reproducible
Fast
Explainable
Free of external AI API dependencies
Safe for demonstration
A production implementation could replace the deterministic decision layer with an LLM/ML-based decision service.

⚠️ Known Limitations
No live financial execution
There is currently no:

Real bank interaction
Live payment-provider transaction
Real refund
Real money movement
Live PSP routing change
Every financial-looking action is a simulation.

API responses and the UI explicitly identify simulated actions.

Deterministic AI/agent engine
The current agent engine uses deterministic rules and heuristics rather than a live LLM.

This keeps the demo reproducible and eliminates external API-key requirements.

A production implementation could replace these decision functions with ML/LLM services.

Development datastore
The JSON-file store is intended for demonstration and development, not production-scale workloads.

WebSocket authentication
WebSocket authentication currently uses a query-string JWT for simplicity.

A production implementation should use a signed, short-lived authentication ticket or another hardened WebSocket authentication mechanism.

🔒 Buildathon Safety & Disclaimer
RecoverX is a buildathon prototype.

It does not move real funds, initiate real refunds, contact banks, or modify live payment-provider routing.

All payment execution, recovery, approval, and routing actions shown in the demo are simulations.

The architecture is intentionally designed so these simulation services can later be replaced with production payment-provider integrations.
